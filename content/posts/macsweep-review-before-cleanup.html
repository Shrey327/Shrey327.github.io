I got tired of managing space on my Mac, so I built MacSweep. Finding a large directory is easy. Deciding whether to remove it is the part that needs more context.

MacSweep is a local macOS disk-cleanup utility with a browser interface. It surfaces large files and cleanup candidates so I can review them before taking action. The design starts with a constraint: nothing should be cleaned automatically just because a scanner found it.

Size is only one input

A large folder might be a disposable build cache, a downloaded model, a working tree or the only copy of a personal file. Sorting all of them by size gives a useful inventory, but it does not establish which ones are safe to remove.

MacSweep adds cleanup context to that inventory. It distinguishes categories and makes review part of the flow. Files that an application can normally regenerate still deserve a warning: regeneration may cost time, bandwidth or a working environment that is no longer easy to recreate.

That wording matters. “Normally regenerable” describes a property of a category. “Safe to delete” would make a stronger claim about a particular user's situation. The tool cannot know that a cache is the last usable copy of an offline dependency or that a worktree contains an uncommitted change.

Prefer a reversible first step

Trash is the default cleanup route. Applications, downloads, large personal directories and worktrees always use that route. The review step remains necessary, but a mistaken selection has a better recovery path than immediate permanent removal.

There are two details worth stating plainly. Moving files to Trash does not reclaim their disk space until Trash is emptied. MacSweep's direct move also does not provide Finder's “Put Back” metadata. Recovery therefore means finding the item in Trash and moving it to the desired location yourself.

A cleanup interface should explain both facts before the user interprets the result. Otherwise it can report a successful move while the user sees no increase in free space, or imply a restoration shortcut that it did not create.

A scan is a snapshot

Time passes between scanning a directory and acting on a selection. Another application can change the filesystem during that interval. The path that appeared in a scan is not enough evidence that the same object is still there when cleanup begins.

MacSweep rechecks file identity before cleanup, pins the parent directory and does not follow symlinks. Scans and cleanup are serialized. These choices address a practical race: a review decision made against one filesystem state should not silently apply to a different object.

This is also why the interface cannot promise that a scan is a permanent truth about the disk. The result is a set of observations to review. The cleanup operation has to validate the relevant observations again at the point of action.

Keep the browser interface local

The application packages a Python runtime and presents its interface in the browser. It binds to loopback and uses a random token for each launch. It has no telemetry and does not request an administrator password.

The browser is the interface, not a cloud destination for a file inventory. That is useful for a tool handling personal paths and directory names. Keeping the service local also keeps the scope small: it is a utility on the current Mac, not a remote fleet-management service.

No administrator prompt also means no claim of unrestricted visibility. Permissions can limit what the application can inspect or change. A tool should make those limits understandable rather than encourage a user to grant broad access just to make a scan look complete.

Packaging is part of usability

The current 1.1 package bundles Python for Intel and Apple Silicon Macs without requiring third-party Python packages. That avoids making someone set up a development environment before using a disk utility.

The build targets macOS 11 and later, but a compatibility target is not evidence of exhaustive testing across every version and machine. The application is ad hoc signed, not notarized. Those are current distribution limits, not details to hide behind the word “native.”

What I want a cleanup tool to do

MacSweep's useful job is to help me understand a selection before removing it. It should show what occupies space, provide relevant context and keep the final decision explicit. It should also be clear about what happened afterward: moved to Trash, skipped because something changed or blocked by permissions.

I am not attaching a claimed number of gigabytes saved or a performance comparison here. Those depend on the disk and workload. The concrete result is a local tool with a review-first cleanup flow, rather than another button that asks me to trust an unexplained “clean” operation.
