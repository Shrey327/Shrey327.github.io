About

Hi, I’m Shreyansh.

I’m interested in how machine learning systems behave when the code meets the hardware.

Most of my work starts with a system I could treat as a black box and builds a small version of it from the parts. An inference server written from the checkpoint up. A reinforcement learning environment where a model has to beat PyTorch on a real GPU. An agent workflow where a person approves each stage. Building them makes the mechanisms concrete. It also makes the measurements mine to defend.

What I work on

  • InferenceX

    Inference · PyTorch · CUDA · Triton

    A Qwen2.5-0.5B inference server with KV caching, continuous batching, paged memory, CUDA graphs and a fused paged attention kernel, built on a 6 GB laptop GPU with a public log of every experiment.

  • KernelEnv

    Reinforcement learning · GPU kernels

    An OpenEnv environment that rewards a model for writing correct, faster Triton kernels, with an evaluator built to resist the shortcuts a policy finds first.

  • GameX

    Agents · Software design

    A human-in-the-loop narrative and asset workflow, examined through its state contracts: approval, revision, partial success and durability.

How I work

  • Predict before measuring. I write down the expected ratio and the mechanism before a benchmark runs. A wrong prediction is the most useful result in the log.
  • Log the failures. Regressions and dead ends get the same entry as wins: command, baseline, result and what it ruled out.
  • Attach the conditions. A number travels with its hardware, workload and baseline. A ratio without those is not a result.
  • Separate shipped from tested. Experimental paths are described as experimental until they run in the default path.
